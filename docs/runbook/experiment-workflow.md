# 实验工作流程

[返回操作入口](README.md) · [实验登记](experiment-register.md) · [产物规则](artifacts.md)

建立日期：2026-10-19。本文规定记录方式，不批准具体训练预算或消融设计。

## 1. 明确问题与协议

探索进入 wiki；用户确认后形成 specs 协议。写明问题、干预、对照、任务规则、数据划分、指标、种子、预算、参数选择和停止条件。
先分配稳定实验编号 EXP-NNN，再登记计划；实际运行目录名称独立记录。同一协议可有多次运行，不能把重复运行当成独立种子。
协议以版本或提交标识引用；重大改变需重新确认，保留旧版本与变更原因。

检查点：用户确认协议及执行范围后才开始实现或运行。

## 2. 固定实现与检查

阅读目标代码，记录拟改文件和现有状态。保存源码提交及未提交差异，不能只保存源码摘要。
按验证范围执行必要检查，登记调用、环境、退出状态和证据位置；失败则记录原因，不进入正式长实验。
短测与长实验分别记录预算；速度外推只是估算，不代替实际资源记录。

检查点：实现及短测通过验收后，按批准预算执行正式运行。

## 3. 执行与恢复

使用新的、可区分的运行名称，不覆盖已有结果。保存解析后的配置、运行清单、环境和随机性信息。
运行状态与证据状态分开维护：完成不等于验证通过；失败或中止也保留记录。
恢复前核查配置、源码、依赖和历史前缀；恢复可能截断快照之后的日志。先确认回滚范围，见产物规则。
禁止为了续训绕过来源校验。若改协议或配置，明确作为新运行或另行设计兼容迁移。

## 4. 分析与结论

从原始记录产生汇总，注明窗口、样本量、种子、基线和排除规则。不得只报告成功种子或最后一个有利窗口。
独立测试与用于调参的验证数据分开；指标定义变化后重新分析须注明版本。
把观察、解释、限制和下一步分开。未优于基线也是结果，不自动触发新算法。

检查点：用户验收结论与下一步，才进入下一个研究阶段。

## 5. 收尾与提交前检查

在实验登记更新实际运行、证据和结论；在 progress 记录阶段状态；关键技术选择进入 decisions。
检查代码与协议是否偏离，把差异交给用户决定，不自动改写原始意图。
检查 Git 差异和文档链接；在用户确认的提交范围内建立回溯点，避免纳入临时文件或大型产物。
产物备份后核对校验值，登记位置。未备份明确标记，不能用“已完成”代替“已归档”。

## 维护触发点

| 事件 | 更新位置 |
| --- | --- |
| 确认或修改协议 | specs + 实验登记中的协议版本 |
| 运行开始、完成、中止或恢复 | 实验登记中的运行状态与证据 |
| 得出结论或发现失败原因 | 实验登记；通用问题另记 pitfalls |
| 技术选择发生变化 | architecture/decisions |
| 阶段结束 | changelog/progress |

当前是人工核查流程，没有安装提交钩子、自动监控或云端服务。
