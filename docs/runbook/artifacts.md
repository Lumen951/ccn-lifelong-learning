## 存储职责

| 内容 | 当前位置 | 保存方式 |
| --- | --- | --- |
| 协议、决策、实验登记和结论 | docs | 随源码版本管理；当前文档尚未提交 |
| 对照入口运行 | results/<name>/ | run.json、metrics.csv、predictions.csv、PT 快照 |
| 原入口运行 | results/<experiment-name>/ | run_<run>.json、runs.csv、error_table.csv、predictions.csv、NPZ 快照 |
| 对比图与汇总 | 以比较工具实际输出为准 | 登记输入运行集合、分析版本和输出位置 |
| 外部备份 | 待用户确定 | 未配置、未执行；不能声称已有异地归档 |

results、build 和 .venv 被 Git 忽略。文档中的 results 路径是本地证据定位信息，克隆后可能不存在，不能视为公开下载地址。
不把所有检查点加入 Git，不自动清理中间快照；容量不足时先列明候选清理项及影响并等待确认。

## 最小可追溯记录

每个运行保存：协议版本、解析后配置、代码提交和未提交差异、依赖环境、种子、数据来源或规则、运行状态、指标与快照位置、校验值、分析来源。
源码摘要用于识别，不是代码备份；Git 提交不包含未跟踪文件和未提交差异。历史运行缺失的字段标记未知，不用当前 HEAD 补填。
清单包含校验值只能提供本地一致性证据，不能证明文件未曾一起被修改。

## 恢复前检查

1. 阅读对应入口的恢复实现和说明，确认目标目录、快照编号及已完成步数。
2. 核对清单与快照的校验值、完整配置、源码摘要和依赖版本。
3. 确认 CSV 前缀兼容及快照之后数据的处理范围；保留需要保留的后续数据。
4. 在原协议与获准范围内恢复，登记恢复起点、调用、结果和异常。

[对照恢复实现](../../experiments/checkpoint.py) 会验证快照、配置、来源及前缀，再截断后续日志；[原入口恢复实现](../../experiment/checkpoint.py) 另有共享 CSV 约束。
仅校验 SHA-256 不等于已验证恢复；未实际运行恢复时明确记录“未测试”。

## 归档验收

记录目标存储位置和访问方式，复制后比对文件清单及校验值，并确认可读取。若希望删除本地副本，须额外确认。
运行完成、证据检查、恢复测试、备份完成四种状态独立记录。
