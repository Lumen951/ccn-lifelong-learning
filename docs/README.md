# 文档导航

本目录保存研究意图、实现依据、实验追踪与证据索引。当前阶段和下一步统一记录在 [进展入口](changelog/README.md)。

## 阅读顺序

1. 阅读根目录 [项目说明](../README.md) 和 [工作约束](../AGENTS.md)。
2. 查看 [进展入口](changelog/README.md)，确定当前获准的工作范围。
3. 按下表读取相关模块，再检查实际代码和运行记录。

## 信息放在哪里

| 模块 | 主要维护内容 | 边界 |
| --- | --- | --- |
| [specs](specs/README.md) | 已确认研究范围、实验协议和验收条件 | 不把候选设计当成已批准方案 |
| [architecture](architecture/README.md) | 代码地图、实现状态和技术决策 | 描述当前实现，并注明待核查项 |
| [runbook](runbook/README.md) | 操作流程、实验登记、验证和产物索引 | 原始结果保留在实际存储位置 |
| [changelog](changelog/README.md) | 已完成变更、阶段交接、阻塞和下一步 | 不重复存储完整协议或实验参数 |
| [vendor](vendor/README.md) | 上游出处、许可证与外部参考 | 不自动下载、执行或复制第三方代码 |
| [wiki](wiki/README.md) | 文献理解、候选问题和探索解释 | 不代表已确认协议或已验证结论 |

## 状态与维护

- 拟议：尚待讨论，不代表获得执行授权。
- 已确认：用户确认了对应范围或协议，仍须区分是否执行。
- 已执行：有实际运行或变更记录，不代表通过验证。
- 已验证：注明验证对象、方法、时间、证据及适用限制。
- 待验收：阶段工作已交付，等待用户决定是否继续。

每项事实只在一个主要位置维护，其他文件使用相对链接引用。日期使用北京时间的日历日期。
未建立的文件仅作为后续计划描述，不添加失效链接。
协议变化保留原因和适用范围，不用新协议覆盖旧运行的真实条件。
历史报告和本次重新核验的证据分别标记；源码摘要用于识别，不能代替可恢复的代码版本。
